# Деплой на Vercel — пошагово

Здесь всё, что нужно, чтобы поднять сайт в интернете. Шаги, где требуется ваш аккаунт и пароли (создание БД, ввод секретов, кнопка Deploy), выполняете вы — это нельзя сделать за вас.

Понадобятся бесплатные аккаунты: **GitHub**, **Vercel** и база **PostgreSQL** (проще всего — Neon или встроенная Vercel Postgres).

---

## Шаг 1. Загрузите код на GitHub

1. Распакуйте архив проекта.
2. Создайте пустой репозиторий на github.com (например `articulem`).
3. В папке проекта выполните:

```bash
git init
git add .
git commit -m "Articulem"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/articulem.git
git push -u origin main
```

---

## Шаг 2. Создайте базу данных PostgreSQL

### Вариант A — Neon (рекомендуется)
1. Зайдите на neon.tech, создайте проект.
2. В разделе **Connection Details** скопируйте строку подключения. Нужны две версии:
   - **Pooled** (с `-pooler` в хосте) → это `DATABASE_URL`.
   - **Direct** (без `-pooler`) → это `DIRECT_URL`.
   Обе должны заканчиваться на `?sslmode=require`.

### Вариант B — Vercel Postgres
1. В проекте Vercel откройте вкладку **Storage → Create Database → Postgres**.
2. Vercel сам добавит переменные `POSTGRES_*`. В этом случае задайте:
   - `DATABASE_URL` = значение `POSTGRES_PRISMA_URL`
   - `DIRECT_URL` = значение `POSTGRES_URL_NON_POOLING`

---

## Шаг 3. Импортируйте проект в Vercel

1. На vercel.com → **Add New → Project** → выберите репозиторий `articulem`.
2. Framework Vercel определит автоматически (**Next.js**). Build-команду менять не нужно.
3. Перед деплоем откройте **Environment Variables** и добавьте:

| Имя | Значение |
|-----|----------|
| `DATABASE_URL` | строка pooled-подключения |
| `DIRECT_URL` | строка direct-подключения |
| `JWT_SECRET` | длинная случайная строка (`openssl rand -base64 32`) |
| `ADMIN_EMAIL` | например `admin@articulem.app` |
| `ADMIN_PASSWORD` | пароль администратора (придумайте свой) |

4. Нажмите **Deploy** и дождитесь сборки.

---

## Шаг 4. Создайте таблицы и наполните базу

Сборка пройдёт, но база ещё пустая. Создайте схему и данные одним из способов.

### Проще всего — с вашего компьютера
В папке проекта создайте файл `.env` с теми же `DATABASE_URL` и `DIRECT_URL`, что и в Vercel, затем выполните:

```bash
npm install
npx prisma db push          # создаёт таблицы в облачной базе по схеме
npm run seed                # админ + авторы + статьи + очередь модерации
```

> `db push` создаёт таблицы напрямую из `schema.prisma` — отдельные файлы миграций не нужны. Если вы предпочитаете версионируемые миграции, выполните локально `npx prisma migrate dev --name init` (создаст папку `prisma/migrations`), закоммитьте её и используйте `npx prisma migrate deploy`.

После этого сайт по адресу `https://ВАШ-ПРОЕКТ.vercel.app` уже работает с данными.

---

## Шаг 5. Войдите как администратор

Откройте `/login` и войдите под `ADMIN_EMAIL` / `ADMIN_PASSWORD`, которые вы задали в переменных. В шапке появится пункт **«Админ»** → `/admin` — там очередь статей на проверку.

---

## Как работает модерация

1. Пользователь регистрируется и на странице **«Создать»** пишет статью.
2. Статья сохраняется со статусом **PENDING** и видна только автору (в профиле, вкладка «На проверке»).
3. Администратор на `/admin` нажимает **«Одобрить»** — статья получает статус **APPROVED**, дату публикации и появляется в общей ленте. Либо **«Отклонить»** с причиной — автор увидит её в профиле.

## Частые вопросы

**Prisma ругается при сборке.** Команда сборки уже включает `prisma generate` (см. `package.json`). Убедитесь, что `DATABASE_URL` и `DIRECT_URL` заданы в переменных окружения Vercel.

**Не входит / сбрасывает сессию.** Проверьте, что `JWT_SECRET` задан и одинаков для всех окружений.

**Нужно сделать ещё одного админа.** Поменяйте поле `role` пользователя на `ADMIN` в базе (например через `npx prisma studio`).

**Хочу очистить демо-данные.** Удалите статьи/пользователей через `npx prisma studio` или пересоздайте базу и запустите `npm run seed` заново.
